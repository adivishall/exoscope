# ExoScope 2.0: Interactive Exoplanet Transit Detection & Discrete Mathematics Lab

ExoScope analyses real Kepler and TESS light curves to find **potential transit candidates**. It shows how
Discrete Mathematics (sets, number theory, graphs, relations and combinatorics) is used to detect, compare,
visualise and evaluate periodic astronomical events.

> ExoScope reports *candidates*. A repeating dip is consistent with a planet, but eclipsing binaries, blended
> stars and instrument effects can look the same. Planetary status needs independent follow-up.

## Quick start

From the folder that contains `exoscope/` (verified on a clean copy, 2026-10-28: install ≈ 30 s with a warm pip
cache, several minutes without one):

```bash
cd exoscope
python3 -m venv .venv                                  # Python 3.11+ (tested on 3.13)
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/streamlit run app.py --server.port 8501 --server.address localhost
```

Then open http://localhost:8501. The first page load takes ~10 s while Astropy imports. On the Home page, click
**Analyse Kepler-8**, **Analyse Kepler-10** or **Analyse synthetic data**. These use bundled real data (or
labelled synthetic data), so the demo works offline. Every page then works on that analysis.

Run the tests and regenerate the results:

```bash
.venv/bin/python -m pytest                     # 94 tests, all passing (maths, detection, storage, reports, every page)
.venv/bin/python scripts/evaluate.py --online  # regenerates docs/EVALUATION.md + docs/results/*.csv (~5 min)
.venv/bin/python scripts/make_figures.py       # regenerates docs/figures/*.png from real results
.venv/bin/python scripts/build_report.py       # docs/REPORT.md → REPORT.html and REPORT.pdf (uses Chrome)
```

## Configuration and data services

No credentials are required. MAST and the NASA Exoplanet Archive are public services.

| Variable | Default | Purpose |
|---|---|---|
| `EXOSCOPE_DB_PATH` | `data/exoscope.db` | SQLite history database (created automatically, no migration step) |
| `EXOSCOPE_CACHE_DIR` | `.cache/` | Downloaded FITS files, search results and compact light-curve copies |

See `.env.example`. Data access works like this:

- **MAST via Lightkurve**: Kepler long-cadence and TESS 2-minute SPOC PDCSAP light curves. The first download
  of a quarter or sector can take about a minute. After that it loads from `.cache/` and also works offline.
- **NASA Exoplanet Archive (TAP)**: known-planet reference values for validation, with a bundled fallback.
- **Bundled samples** (`exoscope/data/samples/`): exact offline copies of real Kepler-8 Q2, Kepler-10 Q3 and
  WASP-18 S2 data. Regenerate them with `python scripts/fetch_samples.py`.
- **Synthetic generator**: clearly labelled SYNTHETIC everywhere. Its injected truth enables exact
  precision and recall.

## Original issues and what changed

The original repository was not available, so v1 was rebuilt from the project description and kept in
`exoscope/legacy.py` for comparison. v1 had a single hard-coded star, flattened the flux, flagged points below
`mean − 3·std`, and took the median spacing of flagged points as the period. Its problems and the fixes:

| v1 issue | v2 change |
|---|---|
| One hard-coded target; no error handling | Any Kepler/TESS target and quarter/sector, two-level cache, offline samples, friendly errors, input validation |
| mean/std biased by the transits | Median and robust MAD noise |
| Every flagged *point* was a "dip"; single noisy points became events | Points grouped into events with a minimum length; depth, duration and SNR per event |
| Median spacing collapses to the cadence or doubles with missed transits | Approximate-GCD period (largest congruence class), refined by least squares |
| One method | Threshold detector and BLS (up to 3 signals) with set-based comparison |
| No vetting | Odd/even, secondary eclipse, box-vs-sine, depth, duration, coverage, SNR, agreement checks |
| No persistence or export | SQLite history, experiment storage, CSV/JSON/Markdown/HTML reports |
| Maths only in prose | Five working Discrete Maths modules driven by real results |

On the same Kepler-8 data, v1's "period" is the cadence (~0.02 d). v2's threshold detector gives 3.5221 d and
BLS gives 3.5231 d; the archive value is 3.5225 d. The About page shows this comparison live.

## Results summary

See `docs/EVALUATION.md` for the full tables, which are generated by `scripts/evaluate.py`.

**Real data (9 known planets, one quarter or sector each, default settings):** BLS recovered every period. The
error against the NASA Exoplanet Archive ranged from 0.001% to 0.22%. The improved threshold detector's
approximate-GCD period was within 0.25% for all 9 and often more precise than BLS, whose period grid is
finite. The legacy v1 method recovered none (its median spacing collapses to the cadence, or is 2.4% off for Kepler-10). Kepler-10 b
(~130 ppm) is the hard case. The threshold detector found 39 events, while BLS found all 102 observed epochs.

**Synthetic benchmark (120 seeded light curves):** period recovery within 1% was 2% for legacy v1, 47% for
the improved threshold detector, and 74% for BLS. At per-point SNR ≥ 3, BLS reached F1 = 1.00. Its failures
are where depth ≤ noise (per-point SNR ≤ 1), where detection is physically marginal over 27 days.

**Injection–recovery on real light curves:** simulated transits were injected into real Kepler data, with each
star's own planet masked out, and into white-noise twins. The 50% recovery depth is about 100 ppm for Kepler-10
(real data recovers 58% at 100 ppm vs 92% for white noise) and about 200 ppm for Kepler-8. The median SNR
penalty of real noise vs white noise is 1.07×.

**Honest errors:** archived per-point errors underestimate the measured scatter by 1.3–1.9×. BLS now scales
them up to match, so the real-data SNRs (e.g. Kepler-10: 43.5) and the 7.1σ gate are not optimistic.

**False positives:** 0/30 pure-noise light curves were reported as significant, and 30/30 eclipsing-binary
imitations were flagged as non-planetary.

**Runtime:** BLS takes ~0.2 s per quarter and the threshold detector < 1 ms (Apple-silicon laptop).

*Fixed during evaluation:* the first run reported 5/10 noise light curves as "possible signals". BLS
searches ~10⁵ period/duration trials, so the strongest noise peak typically reaches SNR 4–6, and the old
checklist graded SNR 5–7.1 as "caution". SNR < 7.1 now counts as *not detected*, and a regression test
covers this.

## Remaining limitations

- Candidates only: no pixel-level/centroid, spectroscopic or radial-velocity vetting.
- BLS uses a box model (no limb darkening), so depths are approximate.
- One quarter or sector per analysis. Planets with fewer than 3 transits in that window cannot be shown to be periodic.
- Checklist thresholds are teaching conventions, not calibrated false-positive probabilities.
- The synthetic benchmark uses white noise, so its scores are optimistic. Real-data validation covers only a few known planets.
- The HTML report loads Plotly from a CDN, so its charts need internet access to display.
